# المعمارية وقرارات التصميم | Architecture & Design Decisions

## 1. نظرة عامة | Overview

معمارية MVC مخصّصة بطبقات صريحة، بلا إطار عمل خارجي (قرار معتمد في المرحلة صفر).

```
HTTP → public/index.php (المتحكّم الأمامي)
   → Application (النواة: البيئة، الإعدادات، الترجمة، معالجة الأخطاء)
   → Router (جدول مسارات صريح)
   → خط الوسائط | Middleware pipeline
        SecurityHeaders → StartSession → VerifyCsrf
        → [ResolveTenant] → [Authenticate] → [Authorize] → [EnforceRateLimit]
   → Controller  (HTTP فقط: تحقق، استدعاء خدمة، اختيار عرض)
   → Service     (قواعد الأعمال، المعاملات، آلات الحالة، التدقيق)
   → Repository  (SQL — العزل بين المنشآت يُفرض هنا)
   → PDO (عبارات مُجهَّزة حصراً)
→ View (قوالب PHP، هروب إجباري عبر e()، نصوص من ملفات الترجمة)
```

**قواعد ثابتة:**
- المتحكّمات لا تحتوي SQL. القوالب لا تحتوي استعلامات ولا قواعد أعمال.
- كل تغيير حالة يمرّ عبر خدمة تكتب السجل وسجل التدقيق داخل معاملة واحدة.
- لا يُقبل `organization_id` من المتصفح إطلاقاً.

## 2. قرارات معمارية مؤثّرة | Key decisions

### 2.1 جدول مسارات صريح بدل الاشتقاق من URL

التطبيق السابق في المستودع كان يشتق اسم المتحكّم والدالة من عنوان URL
(`/foo/bar` → `FooController::bar()`)، ما يجعل **كل دالة عامة نقطة نهاية**.
استُبدل بجدول مسارات في `routes/web.php` يعلن لكل مسار: الأسلوب، الوسائط،
والصلاحية المطلوبة. النتيجة: سطح الصلاحيات كله قابل للتدقيق من ملف واحد،
واختبار `test_controller_methods_are_not_reachable_by_url_guessing` يحرس ذلك.

### 2.2 العزل بين المنشآت كخاصية بنيوية لا كمُرشِّح

`BaseRepository` يرفض بناء أي استعلام على جدول مملوك لمنشأة قبل قرار نطاق صريح:
`scopedToTenant()` أو `globalScope('سبب')`. النسيان يرمي استثناءً بدل أن يُرجع كل
الصفوف. كما تُفرض `organization_id` من نطاق المستودع عند الإنشاء وتُتجاهل أي قيمة
واردة، ولا يمكن نقل الملكية عبر التحديث.

**لماذا 404 لا 403 عند محاولة قراءة سجل منشأة أخرى؟** لأن 403 يؤكد وجود السجل،
فيتحوّل النموذج إلى أداة استكشاف. `findOrFail` يرمي 404.

### 2.3 إعادة التحقق من العضوية في كل طلب

`ResolveTenant` لا يكتفي بقيمة الجلسة: يقرأ صف العضوية من قاعدة البيانات في كل
طلب. إلغاء العضوية أو إيقاف الحساب يسري فوراً على الجلسات الجارية.

### 2.4 صلاحيات ذات مستويين

- **نطاق المنصة** (`user_roles`): مدير المنصة، مسؤول التشغيل، محرّر المحتوى، عميل السوق.
- **نطاق المنشأة** (`organization_members`): صاحب المشروع، الموظف، مسؤول البنك…

الصلاحيات الفعّالة = صلاحيات أدوار المنصة ∪ صلاحيات دور العضوية + تجاوزات المنح
− تجاوزات المنع. **المنع يغلب المنح دائماً**، حتى لا يعيد دورٌ آخر صلاحيةً منعها
صاحب المشروع صراحةً.

### 2.5 أنماط الصلاحيات (wildcards) خطر مُراقَب

استخدام `marketplace.listing.*` في تعريف دور صاحب المشروع كان يلتقط
`marketplace.listing.moderate` — صلاحية إشراف على إعلانات المنشآت الأخرى.
الآن تُسرد الصلاحيات صراحةً حيث يتجاوز النمط الحدود، ويحرس ذلك اختبار
`test_no_organization_role_holds_a_platform_oversight_permission`.

### 2.6 مزامنة المنطقة الزمنية بين PHP وقاعدة البيانات

كانت جلسة قاعدة البيانات تُضبط على `+02:00` ثابتة بينما PHP يعمل بتوقيت
`Africa/Cairo` الذي يطبّق التوقيت الصيفي. الفارق ساعة يُبطل كل مقارنات الصلاحية:
قفل الحساب ينتهي قبل أوانه، ورموز التحقق والاستعادة تبدو منتهية أو صالحة خطأً.
تُحسب الإزاحة الآن من التوقيت الفعلي الحالي.

### 2.7 ترويسات الأمان تشمل صفحات الخطأ

صفحات 404/403/500 تُبنى خارج خط الوسائط (قد يقع الاستثناء قبل مطابقة المسار)،
لذا استُخرج تطبيق الترويسات إلى `SecurityHeaders::apply()` يستدعيه الوسيط
ومعالج الاستثناءات معاً.

### 2.8 أصول مستضافة محلياً

Bootstrap RTL وخط Cairo وملفات JS مخزّنة في `public/assets`. يسمح ذلك بسياسة
محتوى صارمة بلا `unsafe-inline` وبلا مضيفات خارجية، ويقلّل زمن التحميل على
الاتصالات المحدودة.

### 2.9 الترجمة من اليوم الأول

لا نص عربي داخل منطق الأعمال. كل النصوص في `resources/lang/ar/*.php` وتُقرأ عبر
`__()`. إضافة الإنجليزية لاحقاً لا تتطلّب تعديل الكود.

## 3. الاعتماديات ومبرراتها | Dependencies

| الاعتمادية | المبرر |
|---|---|
| `composer` (التحميل التلقائي فقط) | معيار PSR-4، بلا كود تشغيل |
| `phpunit/phpunit` (تطوير) | متطلّب §17 |

قراءة `.env` والتوجيه والتحقق والترحيلات والقوالب مكتوبة يدوياً (~600 سطر).

## 4. نقاط التوسعة | Extension points

| المؤجَّل | نقطة التوسعة الجاهزة |
|---|---|
| بوابات الدفع | `PaymentGatewayInterface` + سجل مزوّدين في `payment_methods` |
| البريد والرسائل | `MailerInterface` / `SmsSenderInterface` + محوّلات تُختار من الإعدادات |
| المحاسبة المزدوجة | بيانات مصدرية على الفواتير والمصروفات تُغذّي خدمة ترحيل لاحقة |
| التكامل مع البنوك والجهات الحكومية | `IntegrationAdapterInterface` + إعدادات بلا بيانات اعتماد في الكود |
| الواجهة الإنجليزية | `resources/lang/en` + أعمدة `name_en` |
| تطبيقات الجوال | نقاط `/api/v1` مع نفس طبقة الخدمات |
